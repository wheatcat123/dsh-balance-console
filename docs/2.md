## 二、逐轮开发记录

### 第 7 轮：需求文档 v1（5 项改动一次性落地）

**需求**（用户文档，含 1 个 Bug + 4 项功能）：① 单轮估价与会话累计估价必须分离（当时两者显示同一个累计值）；② 主面板最新条目置顶并"属于最新时整行着色"；③ 新增钱数阈值 / 警告颜色 / 警告秒数三项设置，高价扣款触发警告色与小窗闪烁；④ 把小窗、主窗、设置窗、估价显示**全部**绑定到侧边栏的 `deepseek-balance` 开关；⑤ 新增"预测下一次对话花费"，显示在输入框上方左对齐。

**实现途径**：

- **Bug ①**：先确认数据源其实早就够用——Host 折叠会话日志时**已经**保留了逐轮明细（`turns[]` 各自带 tokens），只是客户端只取了会话累计。于是只改客户端：`TurnEstimate` 用 `props.turn.turn` 去 `row.turns` 里取**该轮**的 tokens 单独计价；标题旁的入口保持累计。新增的约束是"每轮只能出一个按钮"——`turnTail` 会随每个 assistant 消息渲染，所以加了 `props.turn.end !== undefined` 的判断，只让 Turn 自己的尾巴出按钮。
- **②**：`ledger` 在 Host 端是"最旧在前"，客户端渲染时整体 `reverse()` 一次即最新置顶；为让客户端能判断"哪条是最新"，Host 的 `view()` 新增 `newestChangeAt`（取 ledger 最大时间戳）。颜色规则落到 `LogRow` 上：整行着色靠 `warn` 属性（注入 CSS 变量 `--__dshbc_warn`，作用于井号 / change 文字 / 时间戳），分隔符 `-----` 与填充条保持默认。
- **③**：设置持久化在既有的 storages JSON 里，新增 `warnThreshold`(0.10) / `warnColor`(rgb(34,177,167)) / `warnSeconds`(0.5)；颜色只接受 `rgb(r, g, b)` 字面量（正则校验，Host 与 Client 各一份），非法值回落默认。小窗闪烁按用户选择的口径实现为"整个小窗背景变警告色 + 文字用对比色"；对比色由 `document.documentElement` 上的 `data-ds-theme-source` / `color-scheme` 判定深色或浅色，深色下文字转黑、浅色下转白。
- **④**：改为真正的"服务级开关"——关闭时浮层整棵返回 null，心跳停止 → Host 侧 `isClientActive` 转 false → 自动轮询随之停止；两个估价按钮也读同一开关，关闭时不再发 `sessionEstimates` 请求。
- **⑤ 预测（第一版）**：基于 Host 已返回的会话累计 tokens，按"累积输入 + 平均输出"估算，并用一个命中率阈值切换是否计入输出（当时按用户确认的"≤阈值时计入输出"实现）。

**关键设计决策（均向用户确认后落地）**：预测行挂在 `conversation.input.dock`（输入框上方的全宽槽位）；闪烁对比色不新增设置项，直接读根节点主题；无规则或无历史数据时整行不显示。

**验证**：新增纯函数抽取脚本跑桩数据（预测分支、颜色回退、网格往返、空输入）；两文件 `node --check`；浏览器实测预测行、会话估价按钮、`data-warn` 状态。

**排障记录**：

- 先在页面直接 `fetch` 路由返回 HTML，误判为路由不可达；重试后确认为一次性抖动，接口正常（此后所有页面探测均以 200 + JSON 为准）。
- 该 profile 的 HMR 监听根为 `root: []`，且插件以 `link:` 装入，**软重载换不掉 Host 的 ESM 模块缓存**：用 `plugin_manager` 禁用再启用（`include:balance-console`）只能让行重新挂载，新 `index.js` 仍不生效。此后确立流程：Host 改动一律请用户重启 `dsh web`。

### 第 8 轮：小窗误闪、文案、括号与判定反转

**需求**（用户口头反馈）：① 没有新消费记录时小窗**一直闪**；② 预测文案不要青色，用原风格的白；③ 括号没显示（当时是 `文学目的预计…`）；④ 98% 命中率却判成"文学目的"；⑤ 字号调大一点、改成与输入框右对齐。

**实现途径与根因**：

- **①（真缺陷）**：`useHostState` 每 2–6 秒轮询一次并每次都把最新 ledger 条目重新判定，于是同一笔高价扣款被反复 `arm()`。修法是在警告状态里记住"已经闪过的那个时间戳"（`lastAt`），同一笔只闪一次；同时把预测值的闪烁判据从组件内 `shownRef` 移到模块级，避免重渲染被误判成价格变化。
- **③**：把 `<>` 换成全角引号 `「」`——尖括号在此环境下未能渲染。
- **④（真缺陷）**：语义映射写反了。`hitRate > 阈值` 本应表示**非文学目的**（上下文几乎全是廉价缓存读，不计输出），当时的显示层却把它映射成文学目的。改为函数返回 `nonLiterary` 布尔、显示层取反。
- **②⑤**：预测行颜色改用主题的 `--dsw-alias-label-secondary`（不再自造绿色/青色），字号 11→12px。

**验证**：用真实会话数值（`13,457,920 hit / 285,101 miss / 58,868 out`）复核标签与金额；抽取脚本重跑，覆盖 80% 命中率在阈值 0 / 80 / 90 下的三种结果；页面实测文字与配色。

### 第 9 轮：对齐锚点（三次迭代才收敛）

**需求**：预测行要"和输入框右对齐"，而不是锚在整个对话界面的左边。

**实现途径与三次迭代**：

1. 第一版用 `align-self: flex-end`。实测发现它对齐的是 **composer 列**（右缘 974）而非**输入框卡片**（右缘 871），差 103px。
2. 第二版改成测量 + `padding-right`。**方向错了**：padding 只把文字在盒内推，元素本身没动，右缘仍在 974。
3. 第三版改为测量 + `margin-right`，用 `requestAnimationFrame` + `ResizeObserver` + `MutationObserver` 驱动重测。首次测量发生在预测行尚未挂载时，于是加了"元素出现后再测"的观察机制。

**踩坑**：中途试过"把已生效的 margin 先减掉再算差值"的补偿写法，**符号弄反**，一次就把 `margin-right` 算成 −1 864 万 px。最终放弃依赖自身位置，改为测量**与预测行无关的静态量**——预测行的包含块（`offsetParent`，即 composer 的 seat）与输入框卡片（沿 contenteditable 向上找第一个真正绘制背景的节点）的右缘之差。

**验证**：右缘 871 = 871，偏差 0；随后窗口宽度从 1389 变到 1382，margin 自动从 180 重算为 56，偏差仍为 0。

### 第 10 轮：Host 时区与时段判定的根本修正

**需求**：23:30 被判成峰时段，而设置里是 24 小时制，要求查明。

**根因**：不是 12/24 小时制，而是**时区**。页面所在浏览器解析为 `America/New_York`，Host 进程与用户实际所在的都是 `Asia/Shanghai`，两者相差 12 小时。客户端用浏览器时钟算时段，23:30 被算成纽约的 11:30，恰好落在工作日网格的峰段：

```
Host  23:46 → slot 47 → 网格位 '0'（谷）
浏览器 11:46 → slot 23 → 网格位 '1'（峰）
grid = 000000000000000000111111000011111111000000000000
```

**实现途径**：

- Host 新增时区化取值：`view()` 输出 `hostTimezone / hostHour24 / hostMinute`；时段判定函数支持传入历史时刻（`anchorSlot(anchor, at)`）与按时刻判断星期（`dayTypeAt`）。
- 客户端 `localAnchor` 支持第四个参数"以哪个时刻为准"，并新增 `wallClock()` 按目标时区取时与分（`Intl.DateTimeFormat.formatToParts`）；`dayTypeOf()` 也按目标时区取星期。
- 中途一度让 Host "优先采用客户端传来的 slot"，随即意识到那会把浏览器时区继续注入，于是改为**Host 自己的本地时钟为准**，客户端 slot 仅作无时钟时的兜底。

**验证**：抽取脚本用桩数据核对（`23:30` → slot 47 → 谷；工作日 / 周六在两地时区的星期判定）；浏览器实测 tooltip 由错误的"峰 11:30"变为正确的"谷 23:30-24:00 (Asia/Shanghai)"。

### 第 11 轮：切换会话时的误闪

**需求**：切换会话窗口时小窗/窗口边缘出现青色闪烁，而该特效应当只在单次余额变动超过阈值时出现。

**根因**：第 8 轮留下的"预测值变化也闪烁"逻辑。判定用的 `lastPredict` 是模块级变量，**跨会话保留**，因此一旦切换会话、预测值随之改变，就会调用警告状态，把只属于余额变动的青色特效带出来。

**实现途径**：**彻底移除预测驱动闪烁** —— 全代码仅保留余额扣款超阈值这一处会 `arm()`，并顺带删掉已无引用的 `lastPredict`。

**验证**：全文检索确认只剩一处 `arm()` 调用点；页面实测小窗 `data-warn=0`、chip 背景透明。

### 第 12 轮：按"每轮结束时刻"计价

**需求**：每条对话按**该对话结束时间**的时段估价；会话估价是**多个时间的估价的聚合**；预测则按**现在时段**估价。

**实现途径**：

- **数据前提核实**：先确认会话事件契约里每条事件都带 `time`（Unix epoch 毫秒），即"每轮结束时刻"可取；再确认 Host 折叠时能拿到它。
- Host 侧：折叠时为每轮记录 `at`（`turn/end` 事件的 `time`）；`estimateAllSessions` 改为**逐轮用各自 `at` 推出时段并单独计价、各自向上取整到分**，会话 `total` 改为这些轮次金额之和（保证"聚合 = 各分项之和"），每行返回 `at` 与 `peak`。
- 客户端：新增 `anchorAt(at, timeZone, fallback)` 由时间戳推时段；单轮按钮改用**该轮结束时刻**的时段；会话入口直接取 Host 的求和值，不再用单一时段重算；收据新增"每轮按其结束时段的计价"明细；预测行**仍按当前时段**（`hostAnchor`）。

**排障记录**：Host 改动后忘记同步更新局部变量名（`dayType` / `slot` 在改为 `fallbackDayType` / `fallbackSlot` 后仍被引用），`node --check` 立即暴露并修正。桩件验证：一轮结束在上海时间 11:30（峰，1M 命中 → ¥0.04）、另一轮结束在 00:00（谷 → ¥0.02），会话合计 ¥0.06，三项断言全部通过。

### 第 13 轮：需求文档 v2（预测公式重写、预警分级、误闪）

**需求**（用户文档）：① 修"切换会话时青色闪烁"（与第 11 轮同源的反馈）；② 预测改为**有工程依据的公式**，取消文学用途分类：

```
预估费用 = (预估未命中 + 预估缓存写入) × 未命中单价
         + 预估命中 × 命中单价
         + 预估输出 × 输出单价
预估未命中   = 上一步 uncachedInputTokens + 上一步 outputTokens
预估命中     = 上一步 cacheReadTokens
预估缓存写入 = 上一步 cacheWriteTokens（按未命中单价计费）
预估输出     = 本会话历史各步 outputTokens 的 P50（保守场景取 P85）
```

并要求把 P50/P85 集成在显示位置**左侧的两极按钮**里；③ 高价扣款在"不再是最新"时**保留警告色井号**，且最新的扣款/存款分别是全红/全绿。

**实现途径**：

- **数据来源定位**：先查 `dsh-token-meter` 的投影定义，确认 `tokenUsage` 状态里有 `totals` 与 `last`（后者是最后一步的四个分项桶 `{uncachedInputTokens, outputTokens, cacheReadTokens, cacheWriteTokens}`），但其 **wire view 只暴露 `totals`**，`last` 读不到。因此改由 Host 提供：折叠时同时记录"最后一步的分项"与"每步输出"数组，随 `sessionEstimates` 行下发；每步输出样本限最近 200 步，避免长会话把 payload 撑大（实测样本已累积 433 步）。
- **公式落地**：客户端重写预测函数，严格按上式；缓存写入借 `estimateUsage` 既有的"写入并入未命中桶"语义计费；百分位用**线性插值**实现。
- **两极按钮**：显示位置左侧 `[P50][P85]`，选择存 `localStorage`，切换即时重算（纯计算，不发请求）；tooltip 列出四项 token×单价明细与样本步数。
- **预警分级**：账本行拆成两档颜色——"整行警告色"（最新且高额）与"仅井号警告色"（非最新但高额）。最新存款走默认绿、最新普通扣款走默认红。
- 同时删掉设置窗口里已失效的 `literary hit rate` 输入项，换成公式说明行。

**验证**：抽取脚本覆盖 P0 / P50 / P85 插值（`[10k,20k,30k,40k,50k]` → P85 = 44 000）、四项 token 预估、两档金额、`last` 缺失时的兜底、以及完全无用量时返回 null；页面实测新预测行形态与档位按钮。

### 第 14 轮：时间戳口径与回执柱状图

**需求**：① 回执里"峰 11:00"与时间戳 `23:00:26` 矛盾（主窗口时间戳与真实时间差约 12 小时）；② 柱状图显示每个柱代表的金额；③ 峰时段结束的会话柱用警告色。

**实现途径**：

- **①（真缺陷）**：时间戳此前用**浏览器时区**格式化，而计费时段用 **Host 时区**，同一窗口里两个口径相差 12 小时。改为时间戳一律按 Host 时区渲染（`Intl.DateTimeFormat`），先把时区缺失时的"回落浏览器时钟"作为可选降级；用户随后要求"所有时间统一为 Host 时区"，于是把时区改为**必填**，缺失时显示 `--` 而绝不猜一个错的时钟。
- **②③**：柱状图画布高度 120→132 腾出标注空间，每根柱顶部标出该轮金额（槽宽 < 34px 时自动省略数字）；峰时段柱的填充与首字标签改用警告色。

**验证**：15/15 条时间戳全部落在 Host 时钟上、无占位符（最新三条 `10-13 17:52:54 / 12:14:50 / 12:13:59`，换算回浏览器时区分别是 05:52 / 00:14 / 00:13，正确）；柱状图 8 根柱各带金额，后两根（峰 10:00、峰 11:00）取到警告色 `rgb(34, 177, 167)`。

**诊断记录（值得留在日志里）**：

- 验证时间戳时我用 `Date.UTC(...)` 构造基准瞬间，却按"Host 本地时间"读取，**自己引入了一个 8 小时误差**，一度得出"换算工具算错"的错误结论。最终改用"同一瞬间分别按两时区格式化"这一无歧义比对方式，才确认插件渲染正确。
- 结论：**"DSH 与插件差 12 小时"的根因在这个浏览器进程的时区配置**（`America/New_York`），DSH 原生时间戳用 `date.getHours()`（见 `dsh-client-ui-chat/lib/client.js` 的格式化入口），插件无权修改。

## 四、明确放弃 / 未采用的技术方案

| 方案 | 放弃原因 |
| --- | --- |
| 用 `plugin_manager` 软重载来更新 Host 代码 | 该 profile 的 HMR 监听根为 `root: []` 且插件以 `link:` 装入，禁用再启用只重新挂载行、**不清 Node 的 ESM 模块缓存**；实测两次均返回旧字段。改为请用户重启 `dsh web` |
| 让 Host 采用客户端传来的 slot | 会把浏览器时区的错误时段注入 Host（正是第 10 轮 bug 的来源）；改为 Host 自己的本地时钟为准 |
| 预测值变化时闪烁 | 与"只有余额变动才闪烁"冲突，且会跨会话误触发（第 11 轮）；彻底移除 |
| `padding-right` 做右对齐 | 只移动盒内文字，元素本身不动（第 9 轮） |
| "扣除已生效 margin 再算差值"的补偿测量 | 符号易错（曾算出 −1864 万 px），根因是让测量依赖自身位置；改为测量与元素无关的静态量 |
| 时区缺失时回落浏览器时钟 | 会再次产生"同一窗口两个口径"的矛盾；改为显示 `--` |
| 会话回执再打印三行单价明细 | 一个会话跨多个时段，单一单价表必然与逐轮合计对不上（曾出现上半部相加 ¥4.8497、总计 ¥2.42 的矛盾）；改为逐轮分项 + 合计 |
| 让插件跟随浏览器时区 | 会造成"计费时段按 Host、时间戳按浏览器"的自相矛盾；用户明确要求统一为 Host 时区 |

## 五、关键技术发现（本轮新增）

1. **会话事件自带 `time`**：`SessionEvent` 每条都带 `time`（Unix epoch 毫秒），因此"每轮结束时刻"无需推测，直接取 `turn/end` 事件的 `time`。
2. **`tokenUsage` 投影的 `last` 不下发**：其状态含 `totals` 与 `last`，但 wire view 只有 `totals`。需要"上一步"的分项时必须在 Host 侧自行记录。
3. **浏览器与 Host 可能不同时区**：本环境浏览器为 `America/New_York`、Host 为 `Asia/Shanghai`，相差 12 小时。凡是"按本地时钟判断"的逻辑（时段、时间戳、星期）都必须显式指定时区，`Date.getHours()` 一类的调用是隐患。
4. **`display: contents` 会打断对齐假设**：浮层槽位的包裹节点是 `display: contents`，插件元素实际是更外层 flex 容器的 item，所以 CSS 对齐会落到错误的容器上；需要直接测量目标元素。
5. **`turnTail` 每个 Turn 只渲染一次**，且 `props.turn` 是 `TurnLocation` 对象（`props.turn.turn` 才是轮号，`props.turn.end` 在 Turn 结束后才有）——判"是否该出按钮"用 `turn.end` 比比对 seq 更稳。
6. **`sessionEstimates` 的成本随会话数增长**：它要遍历所有会话日志（折叠结果按 `revision` 缓存）。客户端已加 2 秒 TTL 与并发请求合并；样本已累积到 433 步 / 200 步上限，若会话继续增多，建议改为"只查当前会话"。
